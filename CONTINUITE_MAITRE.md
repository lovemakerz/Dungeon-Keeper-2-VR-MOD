## Rotation native (0.3.1)
- CCamera (pont 0x795700 +0x3E5) : +0xD84 direction (lacet, uint16 & 0x7FF, angle = dir·π/1024), +0xD86 inclinaison (0..0x1CC), +0xD88 roulis/autre. 0x449F50 setDirection(int16*) = écrit +0xD84 puis recalcule la matrice (0x44D6D0). 0x449D40 rotateRel(int16* d84,int16* d88,int16* d86) (utilisé par la commande clavier 0x4422F0). 0x44DC70 = aimantation par 0x100 (commande 0x85).
- Contrôle : direction = direction0 + signe·θmains·1024/π (absolu depuis le début du geste). Signe mesuré : cap de l'axe X monde (ligne 0 de 0x77F458) dans le repère table, variation / variation de direction ≈ ±1.

DLL x86 dans le jeu (interception des sommets XYZRHW via dxwrapper) → reconstruction 3D → rendu par œil dans textures D3D9Ex partagées → hôte OpenXR x64 (D3D11). Protocole mémoire partagée : **version 2** (864 octets) en 0.2.0 ; DLL et hôte doivent être de la même version.

## DÉCISION ARCHITECTURE (prochaine version majeure 0.3.0)
Le ressenti « 60 Hz » vient de ce que le monde n'est redessiné qu'aux images du jeu (40–110 i/s variables) ; le casque ne fait qu'une reprojection d'image. Solution : rendu découplé à la fréquence du casque. Le DLL exporte chaque image (sommets monde + états + textures partagées) ; l'hôte D3D11 redessine la dernière maquette à 90 Hz avec la pose courante (tête et mains parfaitement fluides, animations au rythme du jeu).
